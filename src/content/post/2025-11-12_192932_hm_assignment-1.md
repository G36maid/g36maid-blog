## 2  Changes Made to Improve VM Performance

### System Environment

The VM tests were performed on a Proxmox VE (PVE) host running Ubuntu 22.04.

Host configuration used for the VM: 8 CPU cores, 4 GB RAM.

Nested virtualization is enabled (/sys/module/kvm_intel/parameters/nested=Y), allowing KVM to run inside the PVE VM.

The VM runs Debian 11 with a self-compiled Linux kernel.

### Improvement

To improve the performance of the VM, the following changes were made in QEMU and the Linux kernel configuration:

* **Enable KVM hardware acceleration**: Added `-enable-kvm` to leverage CPU virtualization features.
* **CPU set to host**: Used `-cpu host` to allow the VM to utilize the full instruction set of the host CPU, including AES and AVX.
* **Increase resources**:

  * Memory increased from 1GB to 2GB (`-m 2048`)
  * CPU cores increased from 2 to 4 (`-smp 4`)
  * apply to both for benchmark

* **Optimize virtual devices**:

  * Disk interface changed from IDE to Virtio (`if=virtio`)
  * Network card changed from e1000 to Virtio-net (`-device virtio-net`)

These changes targeted CPU, I/O, and network performance improvements.

* small improvement like change shebang to more general usecase`#!/usr/bin/env bash` to both

### Original VM
```run.sh=
#!/usr/bin/env bash

KERNEL=${KERNEL:-./linux/arch/x86_64/boot/bzImage}
MEM=${MEM:-2048}
SMP=${SMP:-4}
DISK=${DISK:-./debian.raw}
APPEND=${APPEND:-"console=ttyS0 root=/dev/sda1 rw"}

qemu-system-x86_64 \
        -m $MEM -smp $SMP \
        -kernel "$KERNEL" \
        -append "$APPEND" \
        -drive file="$DISK",format=raw,if=ide \
        -netdev user,id=net0 -device e1000,netdev=net0 \
        -nographic

```
### Optimized VM
```fast.sh=
#!/usr/bin/env bash

KERNEL=${KERNEL:-./linux/arch/x86_64/boot/bzImage}
MEM=${MEM:-2048}
SMP=${SMP:-4}
DISK=${DISK:-./debian.raw}
APPEND=${APPEND:-"console=ttyS0 root=/dev/vda1 rw"}

qemu-system-x86_64 \
    -enable-kvm \
    -cpu host \
    -m $MEM -smp $SMP \
    -kernel "$KERNEL" \
    -append "$APPEND" \
    -drive file="$DISK",format=raw,if=virtio \
    -netdev user,id=net0 -device virtio-net,netdev=net0 \
    -nographic

```

## 3. How the New VM Performance Was Measured

The VM performance improvements were measured using CPU, disk, and network benchmarks:

| Resource                     | Slow VM    | Fast VM     | Improvement   |
| ---------------------------- | ---------- | ----------- | ------------- |
| CPU (sysbench events/sec)    | 656.34     | 5525.21     | ~8.4x faster  |
| Disk write speed (`dd`)      | 400 MB/s   | 1.1 GB/s    | ~2.75x faster |
| Disk read speed (`dd`)       | 688 MB/s   | 4.6 GB/s    | ~6.7x faster  |
| Network bandwidth (`iperf3`) | 641 Mbit/s | 1.60 Gbit/s | ~2.5x faster  |

The measurements clearly show that the VM performance improved significantly in all major aspects.

---

## 4. Reasons for Performance Improvement

* **KVM + CPU host**: Using hardware virtualization instructions greatly reduced CPU emulation overhead.
* **Increased cores and memory**: More resources allowed smoother multi-threaded computation and I/O buffering, reducing idle times.
* **Virtio devices**: Paravirtualized disk and network drivers provide lower latency and higher throughput compared to traditional IDE/e1000 devices.

Overall, these changes effectively reduced virtualization bottlenecks and enabled the VM to approach near-native performance.
