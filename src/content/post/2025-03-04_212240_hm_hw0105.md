**JSON & TOML 2-Way Converter (20 pts)**  

JSON is a popular text format for information exchange. You can see the following links to study this format:  
[https://zh.wikipedia.org/wiki/JSON](https://zh.wikipedia.org/wiki/JSON)  
[https://www.json.org/json-en.html](https://www.json.org/json-en.html)  

TOML (Tom's Obvious Minimal Language) is designed to map unambiguously to a hash table. It should be easy to parse into data structures in a wide variety of languages. You can see the following links to study this format:  
[https://en.wikipedia.org/wiki/TOML](https://en.wikipedia.org/wiki/TOML)  
[https://toml.io/en/](https://toml.io/en/)  

---

Jason and Tom are starting a new project, but they are arguing about which format to use—JSON or TOML. Neither is willing to compromise. As an intern in the company, your job is to write a converter that allows them to work seamlessly without conflicts.  

### Task  
You need to implement a **JSON-TOML 2-way converter**. The program should take input in either JSON or TOML format and convert it to the other format.  

For simplicity, you can:  
- **Skip the format check** (assume the input is always valid).  
- **Do your best to support all features of both formats**.  
- **If a feature in one format is not supported in the other, you can transform it into an array representation and get half point on single testcase**.  

---
### Handling Differences  
* Nested Objects: Convert JSON objects to TOML tables
* Inline Tables: Convert inline tables to standard JSON objects
* Arrays: Direct conversion
* Date/Time: Convert TOML date/time to JSON string
* Multi-line Strings: Convert TOML multi-line strings to JSON string array
* Comments: Ignore TOML comments in JSON output
* Numbers: Direct conversion, But...:
    * Integer: Direct
    * Float: Direct
    * Binary, Octal, Hexadecimal: 
    * Infinity: should not implementation
    * NaN: should not implementation
    * Number separators: remove '_' and convert

### **Example 1: JSON → TOML**  
#### **Input**
```sh
$ ./hw0104
Which language is this: JSON
How many lines: 12
Enter your data:
{
  "name": "Jason",
  "age": 25,
  "skills": ["Rust", "C", "Python"],
  "address": {
    "city": "New York",
    "zip": "10001"
  },
  "project": {
    "title": "JSON-TOML Converter",
    "inline_table": {"lang": "TOML", "level": "easy"}
  }
}
```
#### **Output**
```toml
name = "Jason"
age = 25
skills = ["Rust", "C", "Python"]

[address]
city = "New York"
zip = "10001"

[project]
title = "JSON-TOML Converter"

[project.inline_table]
lang = "TOML"
level = "easy"
```

### **Example 2: TOML → JSON**  
#### **Input**
```sh
$ ./hw0104
Which language is this: TOML
How many lines: 10
Enter your data:
title = "TOML to JSON Converter"
version = 1.2
release_date = 2025-03-05T12:00:00Z
authors = ["Jason", "Tom"]

[config]
enabled = true
multi_line_string = """This is
a multi-line
string."""
```
#### **Output**
```json
{
  "title": "TOML to JSON Converter",
  "version": 1.2,
  "release_date": "2025-03-05T12:00:00Z",
  "authors": ["Jason", "Tom"],
  "config": {
    "enabled": true,
    "multi_line_string": "This is\na multi-line\nstring."
  }
}

```

### **Example 3: Handling Unsupported Features**  
#### **Input (TOML with comments and special features)**
```sh
$ ./hw0104
Which language is this: TOML
How many lines: 9
Enter your data:
# This is a comment
server = "production"
ports = [8080, 443]
config = { mode = "auto", retry = 3 }

[logging]
level = "debug"
timestamp = 2025-03-05T15:30:00Z
```
#### **Output (JSON ignores comments and converts inline table)**
```json
{
  "server": "production",
  "ports": [8080, 443],
  "config": {
    "mode": "auto",
    "retry": 3
  },
  "logging": {
    "level": "debug",
    "timestamp": "2025-03-05T15:30:00Z"
  }
}
```

### **Constraints**  
- The input contains **at most 8192 characters**.  
- **Keys and values** will be properly formatted for their respective formats.  
- You **cannot use any existing JSON or TOML libraries**.
