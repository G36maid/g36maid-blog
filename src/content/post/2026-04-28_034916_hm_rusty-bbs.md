### 2. 技術堆疊選型 (The Stack)

* **語言:** Rust (Edition 2024/2021)
* **Database:** PostgreSQL (透過 `docker-compose` 啟動)
* **ORM/Query:** **SQLx** (非同步、編譯期檢查 SQL，最適合系統工程師)
* **Web Layer:** **Axum** (Tokio 官方維護，人體工學佳，效能頂級)
* **Web Frontend:** **Askama** (Type-safe Jinja-like templates) + **HTMX** (互動) + **Tailwind** (樣式)。
* *理由：* 這樣可以讓 Web 和 SSH 共用同樣的 Rust Structs 資料結構。


* **SSH Layer:** **Russh** (處理 SSH 握手協定) + **Ratatui** (繪製 TUI 介面)。
* *理由：* `Russh` 是目前 Rust 生態最成熟的純 Rust SSH 實作；`Ratatui` 是 TUI 的標準。

### 4. 實作計畫 (Implementation Plan)

#### Phase 1: 基礎設施 (Infrastructure)

目標：跑起 Docker，連上 DB。

**`docker-compose.yml`**:

```yaml
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: bbs_user
      POSTGRES_PASSWORD: bbs_password
      POSTGRES_DB: rusty_bbs
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

  app:
    build: .
    ports:
      - "3000:3000" # Web
      - "2222:2222" # SSH
    depends_on:
      - db
    environment:
      DATABASE_URL: postgres://bbs_user:bbs_password@db:5432/rusty_bbs
      RUST_LOG: info

volumes:
  postgres_data:

```

#### Phase 2: 核心邏輯與資料庫 (The Core)

目標：定義資料結構，確保 SQLx 編譯通過。

1. **Schema (`migrations/`):**
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    ssh_key TEXT, -- 用於 SSH 自動登入
    is_admin BOOLEAN DEFAULT FALSE
);

CREATE TABLE boards (
    id SERIAL PRIMARY KEY,
    slug VARCHAR(20) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL
);

CREATE TABLE posts (
    id SERIAL PRIMARY KEY,
    board_id INTEGER REFERENCES boards(id),
    user_id INTEGER REFERENCES users(id),
    content TEXT NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

```


2. **Models (`src/models/`):** 定義對應的 Rust Struct，並 derive `sqlx::FromRow`。

#### Phase 3: 雙頭啟動 (The Dual Head)

這是最關鍵的一步。在 `main.rs` 中，你需要用 `tokio::spawn` 讓兩個 Server 並行運作。

**`src/main.rs` (概念代碼):**

```rust
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let pool = db::init_pool().await?;

    // 1. 啟動 Web Server (Axum)
    let web_pool = pool.clone();
    let web_handle = tokio::spawn(async move {
        web::start_server(web_pool).await
    });

    // 2. 啟動 SSH Server (Russh)
    let ssh_pool = pool.clone();
    let ssh_handle = tokio::spawn(async move {
        ssh::start_server(ssh_pool).await
    });

    // 等待任一服務結束 (通常是 Ctrl+C)
    let _ = tokio::join!(web_handle, ssh_handle);
    Ok(())
}

```

#### Phase 4: SSH/TUI 實作 (The Hard Part)

這是最具挑戰性但也最有趣的部分。

1. **SSH Server (`src/ssh/server.rs`):**
* 實作 `russh::server::Handler` trait。
* 當 `channel_open_session` 被呼叫時，建立一個新的 Session。
* 處理 PTY (Pseudo-Terminal) 請求（這是 TUI 能跑的關鍵）。


2. **TUI Loop (`src/ssh/tui.rs`):**
* 初始化 `ratatui::Terminal`。
* 使用 `crossterm` 作為 backend (注意：在 SSH over network 的環境下，需要將 output stream 導向 `russh` 的 Channel，而不是本地的 stdout。這通常需要一個轉接層 Adapter)。
* **事件迴圈 (Event Loop):**
* 接收 SSH 輸入 (Key Events)。
* 更新 App State (游標移動、換頁)。
* `terminal.draw()` 重新繪製 UI。





#### Phase 5: Web 實作 (The Standard Part)

1. **Templates (`src/web/templates.rs`):** 使用 Askama 定義 `BoardListTemplate`, `PostTemplate`。
2. **Handlers (`src/web/routes.rs`):**
* `GET /`: 回傳看板列表 HTML。
* `GET /board/:slug`: 回傳文章列表。
* `POST /post`: 接收 Form data，寫入 DB，回傳 HTMX snippet 更新列表。

### 5. 開發路徑建議 (Next Steps)

這是一個大工程，我建議你依照以下順序「切片」執行：

1. **Week 1: Skeleton & DB**
* 寫好 Docker-compose。
* 用 SQLx 寫一個簡單的 `SELECT 1` 確保連線成功。
* 用 Axum 寫一個 Hello World。


2. **Week 2: The SSH Prototype**
* 先別管 DB。
* 引入 `russh`，寫一個能讓你有 `ssh localhost -p 2222` 連進去，並看到 "Welcome to Rusty BBS" 純文字的 Server。
* *難點預警：* 理解 Russh 的 Handler callback 機制。


3. **Week 3: TUI Integration**
* 在 SSH 連線中引入 `ratatui`。
* 試著畫出一個簡單的列表（假資料）。


4. **Week 4: Logic Connection**
* 把 DB 的資料餵給 Web 和 SSH。
* 實作「發文」功能。
