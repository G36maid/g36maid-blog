```=
function hashNameAndRotations(name, L, d, Q):
    n = length(name)
    hashValues = []

    // Convert characters to ASCII codes
    asciiCodes = []
    for i = 0 to n-1:
        asciiCodes[i] = ASCII(name[i])

    // Compute initial hash value for the name
    hashValue = 0
    for i = 0 to L-1:
        hashValue = (hashValue * d + asciiCodes[i]) mod Q

    // Store hash value for the initial name
    hashValues.append(hashValue)

    // Compute hash values for name rotations
    for i = 1 to L-1:
        // Update hash value for each rotation
        hashValue = (d * (hashValue - d^(L-1) * asciiCodes[i-1]) + asciiCodes[i+L-1]) mod Q

        // Store hash value for the rotation
        hashValues.append(hashValue)

    return hashValues
```

### 4. 

In both hashing problems, Lin is using a hashing function that maps strings to a range of values between 0 and P-1, where P is a prime number (P = 10^9 + 7). The goal is to determine certain conditions based on the hash values of the strings.

(a) Given a string key and a set S of n strings, the objective is to determine if there exists any string si in S that is equal to the key. Lin received AC (Accepted) for this problem, which means her solution is correct.

The reason Lin's solution is correct is because the hashing function she uses is designed to distribute the hash values uniformly among the range [0, P-1]. This means that each string in the set S will have a unique hash value with a high probability. Therefore, Lin can use the hash value of the key to quickly identify whether there is a string in the set S that matches the key.

(b) Given a set S of n strings, the objective is to determine if there exist two strings si and sj (where i is not equal to j) in S that are equal to each other. Lin received WA (Wrong Answer) for this problem, which means her solution is incorrect.

The reason Lin's solution is incorrect is due to the possibility of spurious hits, also known as hash collisions. A hash collision occurs when two different strings produce the same hash value. While Lin's hashing function aims to distribute the hash values uniformly, collisions can still occur due to the pigeonhole principle.

With a set S containing n strings (n = 10^5), the likelihood of hash collisions increases. As P is a large prime number, the chance of a spurious hit (collision) happening for any specific pair of strings is relatively low. However, when the number of strings in the set is large, the overall probability of at least one collision increases.

## 3. 

1. When we insert a new node into the RB tree, we make sure the tree remains balanced by performing rotations if necessary. This ensures that the height of the tree stays logarithmic in relation to the number of nodes.

2. During the insertion or deletion process, we also update the size of the nodes. If a rotation occurs, we update the size of the rotated node as well.

The time complexity of each insert or delete operation in an RB tree is O(log(n)). 

By updating the sizes from the new node that was inserted or deleted up to the root of the tree, we cover the height of the tree, the time complexity of this updating process is also O(log(n)).
