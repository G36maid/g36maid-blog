八月中的時候我讓 agent 幫我整理知識庫，事後翻它的產物，發現一件很討厭的事：有些寫進文件裡的「事實」根本沒有來源。某段描述裡的細節，我往上追了半天，追到的源頭竟然是 agent 自己先前寫的另一份筆記；任何我看過、驗證過的紀錄裡都沒有這段內容。也就是說，第一個 session 幻覺出了幾個細節，把它們寫成一本正經的文件；之後的 session 把那份文件當成知識庫的正文讀進上下文，不但照單全收，還在後續的整理裡繼續引用、繼續擴寫。幻覺就這樣從「一次生成裡的雜訊」變成「有文件的既成事實」，開始在好幾個 session 之間巡迴演出。

當下我只有一個感想：整個就是傻子共振。寫入的傻子憑空補了細節，回讀的傻子把它當真，然後兩個傻子加起來比一個傻子還篤定。單一 session 的幻覺我早就習慣了，抽問一下就能戳破；麻煩的是寫進文件之後，它取得了一種「白紙黑字」的地位，之後每個 session 讀進來，都跟真實紀錄放在同一個上下文裡，同樣的權重、同樣的口吻。我沒辦法從文字上分辨哪一行是我親自驗證過的、哪一行是 agent 上個月編的。知識庫本來是我用來省 context 的工具，結果變成了污染源。

冷靜下來之後我把這個循環拆開看，發現結構其實很單純：agent 的知識庫和記憶檔案，本質上是一個「寫入後回讀」的閉環。模型在 session 裡產生文件，文件被存下來，下一個 session 啟動時又把這些文件載入上下文。問題出在回讀這一步：模型對自己——或者對別的模型——寫的文件，沒有任何來源標記可用。讀進來的文字就是文字，幻覺寫的結論和我貼的筆記，在 token 層面長得一模一樣。Claude Code 的記憶機制就是明顯的例子，CLAUDE.md 這類檔案被設計成每次啟動自動載入（見[官方文件](https://docs.claude.com/en/docs/agents-and-tools/claude-code/memory)），載入的時候可沒有附一張「以下內容可信度未知」的標籤。Anthropic 在 context engineering 那篇長文裡也講，agent 在迴圈裡會不斷產生新的資料，需要「循環地精煉」才知道哪些該留下、哪些該丟掉（[Effective context engineering for AI agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)）——但實務上多數 agent 整理知識庫時只做「寫入」，精煉那步是缺席的。

這件事放大量來看，跟 model collapse 是同一個故事。Shumailov 等人在 Nature 2024 的論文證明，模型如果大量訓練在自己（或前代模型）生成的資料上，原始分佈的尾部會逐漸消失，模型輸出收斂到一個方差極小的平均值，作者稱之為 model collapse（[AI models collapse when trained on recursively generated data](https://www.nature.com/articles/s41586-024-07566-y)，[arXiv 版本](https://arxiv.org/abs/2305.17493)）。我的知識庫規模當然遠小於網際網路，閉環也沒有真的重新訓練權重，但模式是同構的：生成物未經過濾地回流成輸入，錯誤的尾巴不會被修正，只會被反覆抄寫，抄到每個 session 都相信它。差別只在於論文裡丟失的是分佈的尾部，我這裡丟失的是「我還記得哪些東西是真的」這件事。

之後我把整理知識庫的流程改了幾個地方，都是對著上面這個閉環下手。第一是 provenance：agent 寫進知識庫的每一條，現在一定標來源和時間，並且把「我驗證過的」和「agent 宣稱的」分成兩個區塊，後者只算線索，永遠不當結論引用。這招其實跟我在[偏好蒸餾](/blog/gemini-preference-distillation/)裡用的思路一樣——與其相信 agent 當下的輸出，不如讓它把來源攤開來，讓下一個讀者（通常還是 agent，但有時是我）有東西可以驗。第二是定期人工收斂：每隔一段時間我把記憶檔匯出來，自己讀一遍，把重複的合併、把可疑的標記或刪掉。機器抄寫會放大雜訊，人讀一遍雖然慢，卻是閉環裡唯一確定不帶幻覺的濾波器。prompt 也是同樣待遇，我讓它維持版本化、每次改動有理由可查（見[prompt 演化](/blog/system-prompt-evolution/)），理由會說謊的時候至少改動本身藏不住。

第三條最違反直覺但最重要：我把 agent 產的所有文件預設成不可信輸入。任何要拿去做決定的數字、路徑、版本號，一律回去原始來源重查一次，就算那段文字寫得再篤定也一樣——寫得越篤定越要查，因為我那次踩雷的文件就是通篇篤定的口吻。多 agent 的場景更是如此，[之前分析過](/blog/multi-agent-security-analysis/)，agent 之間互傳的報告要當成帶毒的信件處理，先消毒再執行，這裡的道理完全相通：下游的模型不會幫你驗上游寫的東西，驗證的責任只能落在閉環外面。

傻子共振沒有辦法根治，因為寫入的傻子和回讀的傻子是同一個模型，你不可能叫它對自己的輸出天生存疑。能做的是在閉環上鑿幾個洞，讓真實來源和人類的判斷有固定進場的位置。八月那次之後，我的知識庫又長出過幾條可疑的斷言，但這次它們被關在「agent 宣稱」那區，污染不了別的段落——對我來說，這就是夠用的勝利。
