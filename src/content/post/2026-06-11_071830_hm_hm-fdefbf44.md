### 1. 早期願景：從 Grit 到高度可自訂的 Atomicity [[02:08]()]

GitHub 創辦人 Chris Wanstrath 最初的願景是打造一個現代化且高度可駭客化 (Hackable) 的開源編輯器。有別於學習曲線陡峭且依賴專有設定語言的 Emacs，他希望能利用熟悉的網頁前端技術（HTML / CSS / JavaScript），降低開發者自訂介面與擴充功能的門檻。

### 2. 技術突破與 Trade-offs：Atom Shell (Electron) 的誕生 [[05:24]()]

經過多次技術迭代，團隊將 Chromium 渲染引擎與 Node.js 結合，開發出了名為 Atom Shell 的底層框架。這項創舉讓原本受限於瀏覽器的前端技術，得以擁有存取系統底層 API 的能力，進而轉化為跨平台的桌面應用程式。

* 優勢 (Pros)：跨平台（Linux、Windows、macOS）的開發成本極低，擁有快速的迭代週期，且能大幅度重用網頁前端的程式碼。
* 劣勢與代價 (Cons)：每一次啟動 Electron 應用程式，底層都必須載入一整個 Chromium 引擎與 Node.js Runtime。 這種「包裝完整瀏覽器」的沉重架構帶來了極高的 Overhead。影片指出，Atom 即便只是開啟一個 2MB 的文本檔案，也可能耗時超過 3 秒並佔據 400MB 的記憶體，對於系統資源的管理相當缺乏效率 [[12:48]()]。

### 3. 微軟的降維打擊：VS Code 的架構最佳化 [[14:17]()]

微軟當時正開發基於瀏覽器的編輯器專案 Monaco，隨後他們直接採用了開源的 Atom Shell (Electron) 框架，並在短短六個月內推出了 Visual Studio Code (VS Code)。面對同樣臃腫的 Electron 架構，VS Code 卻能達到比 Atom 快上四倍的效能，關鍵在於以下核心工程設計 [[15:31]()]：

* 擴充套件的隔離執行緒 (Isolated Processes)：VS Code 的 Extensions 運行於獨立的進程中，採用非同步 (Async) 的方式載入，不會阻擋主體的 UI 執行緒。開發者在開啟 VS Code 的瞬間就能直接編輯檔案，無需等待底層套件全部載入完畢。
* Monaco 引擎底層調校：作為 VS Code 核心的 Monaco 引擎，在整合進 Electron 之前就已經過嚴格的最佳化與測試。
* 二進位編碼傳輸 (Binary Encoding)：VS Code 在內部狀態傳輸與資料儲存時，優先採用 Binary 格式而非純文字 (Text)，大幅降低了系統的記憶體與儲存空間開銷。

### 4. 商業收購與 Atom 的終局 [[17:14]()]

2018 年，微軟以 75 億美元收購 GitHub。儘管初期官方公開承諾會同時支援並維護 Atom 與 VS Code，但隨著 VS Code 持續釋出高頻率的迭代更新，開源社群的核心貢獻者逐漸向 VS Code 靠攏。Atom 的 Commit 頻率在半年內銳減 76%，最終於 2022 年正式被微軟宣告終止維護 (Sunsetting) [[19:15]()]。

### 5. 精神延續：現代開源編輯器的重生 [[20:06]()]

* 底層架構的重構與 Zed：在記取了 Electron 框架對記憶體與系統資源過度消耗的教訓後，三位 Atom 核心貢獻者選擇改以 Rust 這類具備 Low-level 控制力與極致多執行緒效能的語言，從零打造出專注於效能的開源編輯器 Zed。對於專精於 Rust、追求系統環境純粹性與高效能的開發者而言，參與並貢獻這類解決底層瓶頸的開源專案，正是推動現代工具鏈演進的重要基石。
* AI 整合的 Cursor：另有團隊直接 Fork 了 VS Code 的開源版本，專注於深度整合 AI 輔助，開發出目前極受矚目的 Cursor 編輯器。
* 結語：Atom 的本體雖然消亡，但其催生出的 Electron 架構，如今支撐著 Slack、Discord 以及擊敗它的 VS Code 等龐大生態系。在開源文化中，程式碼與技術理念總會透過競爭與 Fork 的方式，在繼承者的專案中持續運作 [[20:42]()]。

### 投稿用相關資訊

編輯器的歷史、現況與未來：從 Electron 到 Rust 與 GPU 驅動的現代化架構 (以 Zed 為例)
Talk 30 min

#### 摘要

現代開發者對編輯器的依賴與日俱增，但底層架構的選擇卻決定了效能的上限。過去十年間，Atom 的誕生將 Web 前端技術（DOM/JS）帶入桌面應用，催生了 Electron 框架，並奠定了 VS Code 的統治地位。然而，這種「包裝完整瀏覽器」的架構也帶來了記憶體消耗與啟動延遲的 Trade-offs。

本議程將帶領聽眾回顧這段第二次「編輯器之戰」的歷史，並將焦點轉向破局者——由 Atom 核心團隊重頭打造的開源編輯器 Zed。

我們將深入探討 Zed 放棄 Web 框架，轉向 Low-level 系統程式語言的關鍵決策。解析其如何利用 Rust 搭配自研的 GPUI 框架（Immediate Mode GUI），將 UI 元件直接交由 GPU 渲染，突破物理限制，實現 120 FPS 的極致效能。此外，議程也將探討現代編輯器如何原生整合 AI 代理，剖析 Model Context Protocol (MCP) 與 Agent Client Protocol (ACP) 的實作架構。

最後，講者將分享參與 Zed 核心開源專案的實務經驗，以及這個社群如何發展到現在的。
