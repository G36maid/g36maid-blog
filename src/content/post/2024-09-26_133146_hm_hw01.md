## 問題 1
The following is a simple function that divides the input by 73 and returns the result:

int div2(int num) {
    return num / 73;
}
Here is the compiled assembly for RISC-V using GCC: (https://godbolt.org/z/1Ynx94PjzLinks to an external site.)

div73(int):
        li      a5,-529514496
        addi    a5,a5,-2019
        mulh    a5,a0,a5
        srai    a4,a0,31
        add     a5,a5,a0
        srai    a5,a5,6
        sub     a0,a5,a4
        ret
This version contains 7 instructions.

Alternatively, the same function could be implemented in only 3 instructions:

div73(int):
        li      a1,73
        div     a0,a0,a1
        ret
In the 7-instruction version, there is no explicit division instruction. Instead, it uses shifts, additions, and multiplications to perform the division. Interestingly, the number "73" is not directly present in this version either.

Why does the compiler generate the 7-instruction version instead of the simpler 3-instruction version? Is using fewer instructions always preferable?

Discuss this with the concepts covered in Chapter 1.
### ans
Using the div (division) instruction, which is more costly in terms of execution time on many RISC-V processors.

The div instruction can cost anywhere from 5 to 40+ cycles on typical hardware, depending on the processor's division capabilities.
On processors without a dedicated division unit, the cost may exceed 100 cycles.
This high cost is why compilers often prefer to replace division with cheaper operations (e.g., shifts and multiplications), especially when dividing by a constant.
 
## 問題 2
A common pitfall is to utilize a subset of the performance equation as a performance metric. To illustrate this, consider the following two processors. P1 has a clock rate of 4.5 GHz, average CPI of 0.9, and requires the execution of 5.0E9 instructions. P2 has a clock rate of 3 GHz, an average CPI of 0.7, and requires the execution of 1.0E9 instructions.

a. One usual fallacy is to consider the computer with the largest clock rate as having the highest performance. Check if this is true for P1 and P2.

b. Another fallacy is to consider that the processor executing the largest number of instructions will need a larger CPU time.
Considering that processor P1 is executing a sequence of 1.0E9 instructions and that the CPI of processors P1 and P2 do not change, determine the number of instructions that P2 can execute in the same time that P1 needs to execute 1.0E9 instructions.

c. A common fallacy is to use MIPS (millions of instructions per second) to compare the performance of two different processors, and consider that the processor with the largest MIPS has the largest performance. Check if this is true for P1 and P2.
### a
The fallacy of assuming that a computer with a higher clock rate automatically has better performance can be tested by comparing the execution times of P1 and P2, as we've calculated earlier.

**For P1:**
- Clock rate = 4.5 GHz
- Execution time = 1 second

**For P2:**
- Clock rate = 3.0 GHz
- Execution time = 0.2333 seconds

### Analysis:
Even though P1 has a higher clock rate (4.5 GHz vs. 3.0 GHz), it takes longer (1 second) to execute the given workload compared to P2, which takes only 0.2333 seconds. This shows that **P2 has better performance**, despite its lower clock rate.

Thus, the fallacy is evident here: **a higher clock rate does not always guarantee better performance**. The total performance also depends on other factors such as the number of instructions to execute and the processor's CPI (Cycles Per Instruction). In this case, P2 executes fewer instructions and has a lower CPI, leading to better performance despite the lower clock rate.
### b
To determine the number of instructions that processor P2 can execute in the same time it takes for P1 to execute 1.0E9 (1 billion) instructions, we first calculate the time required for P1 to execute 1 billion instructions. Then, using that time, we find how many instructions P2 can execute within the same duration.

### 1. Calculate the execution time for P1 to execute 1.0E9 instructions:
The execution time for P1 is given by the formula:
\[
\text{Execution Time}_{P1} = \frac{\text{Instruction Count} \times \text{CPI}_{P1}}{\text{Clock Rate}_{P1}}
\]

For P1:
- Instruction Count = \( 1.0 \times 10^9 \)
- CPI = 0.9
- Clock Rate = 4.5 GHz = \( 4.5 \times 10^9 \) cycles per second

\[
\text{Execution Time}_{P1} = \frac{1.0 \times 10^9 \times 0.9}{4.5 \times 10^9} = 0.2 \, \text{seconds}
\]

### 2. Determine how many instructions P2 can execute in 0.2 seconds:
The number of instructions P2 can execute is given by:
\[
\text{Instruction Count}_{P2} = \frac{\text{Execution Time}_{P1} \times \text{Clock Rate}_{P2}}{\text{CPI}_{P2}}
\]

For P2:
- Execution Time = 0.2 seconds (same as P1's time)
- Clock Rate = 3.0 GHz = \( 3.0 \times 10^9 \) cycles per second
- CPI = 0.7

\[
\text{Instruction Count}_{P2} = \frac{0.2 \times 3.0 \times 10^9}{0.7} = \frac{0.6 \times 10^9}{0.7} \approx 0.857 \times 10^9 = 857 \, \text{million instructions}
\]

### Conclusion:
In the same time that P1 needs to execute 1.0 billion instructions, P2 can execute approximately **857 million instructions**.

This demonstrates that executing more instructions doesn't necessarily mean requiring more CPU time. P1 executes more instructions in general but requires more time due to a higher CPI, while P2 is more efficient despite executing fewer instructions.
### c
To determine whether the fallacy of using MIPS (Millions of Instructions Per Second) holds true for comparing the performance of P1 and P2, let's first calculate the MIPS for both processors and then assess their performance based on execution time.

### 1. Formula for MIPS:
MIPS is calculated as:
\[
\text{MIPS} = \frac{\text{Clock Rate} \times 10^6}{\text{CPI}}
\]
This formula gives the number of millions of instructions a processor can execute per second.

### 2. Calculate the MIPS for P1:
For P1:
- Clock Rate = 4.5 GHz = \( 4.5 \times 10^9 \) cycles per second
- CPI = 0.9

\[
\text{MIPS}_{P1} = \frac{4.5 \times 10^9 \times 10^6}{0.9} = \frac{4.5 \times 10^{15}}{0.9} = 5 \times 10^9 \, \text{MIPS} = 5000 \, \text{MIPS}
\]

### 3. Calculate the MIPS for P2:
For P2:
- Clock Rate = 3.0 GHz = \( 3.0 \times 10^9 \) cycles per second
- CPI = 0.7

\[
\text{MIPS}_{P2} = \frac{3.0 \times 10^9 \times 10^6}{0.7} = \frac{3.0 \times 10^{15}}{0.7} \approx 4.29 \times 10^9 \, \text{MIPS} = 4290 \, \text{MIPS}
\]

### 4. Comparison:
- **MIPS for P1** = 5000 MIPS
- **MIPS for P2** = 4290 MIPS

By this metric alone, it seems that P1 has the higher performance, since it has a higher MIPS value.

### 5. Reality Check: Execution Time
However, as we calculated earlier:
- **Execution time for P1** = 1 second
- **Execution time for P2** = 0.2333 seconds

P2 has a **shorter execution time** than P1, which means P2 actually has better performance despite having a lower MIPS value.

### Conclusion:
This example demonstrates that using MIPS as a sole measure of performance is misleading. **MIPS does not accurately reflect overall performance**, as it only considers instruction execution rate without accounting for factors such as the number of instructions, CPI, and overall execution time. Even though P1 has a higher MIPS value, **P2 has better performance** in terms of actual execution time.

Thus, the fallacy holds true: the processor with the largest MIPS does not necessarily have the best performance.
