## 2. Naughty Friend, Sana
### (a) 解釋 NFS 的標準認證機制 (AUTH_SYS)

NFS (Network File System) 是一種用於在不同機器之間共享文件的協議，而 AUTH_SYS 是其標準認證機制之一。

在 AUTH_SYS 認證機制中，客戶端對伺服器發送請求時，將在每個 RPC （Remote Procedure Call）中傳遞用戶和群組的數字 UID（User ID）和 GID（Group ID）。伺服器使用這些 UID 和 GID 來決定客戶端是否被授權訪問特定資源。

AUTH_SYS 不建議用於對安全性要求較高的環境，特別是在公共網絡上。

對於需要更強認證機制的場景，NFS 還提供了其他的認證方式，如 Kerberos 認證，它提供了更強的安全性保護。

### 3. Nasa Finds krb5

(a) RPCSEC_GSS 認證模式
RPCSEC_GSS是一種用於遠程過程呼叫（RPC）安全認證的機制。它基於通用安全服務（GSS）API實現認證和數據保密性。

當與 Kerberos 結合使用時，RPCSEC_GSS 能夠對 NFS 進行強化安全保護，所以沒有有適當權限的情況將無法下達訪問文件系統。

<div style="page-break-after:always;"></div>


(b) 設定 RPCSEC_GSS 和 Kerberos
建立 Kerberos KDC：我直接拿 nfs-client 複製來設定，並且 table 如以下

192.168.30.1 nfs-server
192.168.30.2 nfs-client
192.168.30.3 kdc-server
配置 KDC Server：

1. 更改 IP 地址以避免網絡衝突。
2. 同步所有虛擬機器的時間，
3. 設定 Key Distribution Center (KDC) 的 krb5.conf 文件，包括設定 realm、KDC 的地址等。
4. 創建並管理使用者帳號和密碼。
5. 設定主機的訪問規則和遠程管理選項。
6. 配置 KDC Client：
    - 配置客戶端的 krb5.conf 文件。
    - 獲取並管理 Kerberos 票據，通常使用 kinit 命令。
7. 更新 NFS 客戶端的認證設定，以使用 RPCSEC_GSS。
8. 測試：在所有設置完成後，進行測試以確保 Kerberos 認證正常工作，並且 NFS 掛載使用了 RPCSEC_GSS 安全選項。
9. 驗證新認證方法：在設定完成後，嘗試重現 Sana 的惡作劇來測試系統的安全性。

因為現在使用了 Kerberos 認證，任何未經授權的修改都應該會被阻止。查看安全日誌文件，確認未授權的存取嘗試是否被 Kerberos 的保護機制攔截。
