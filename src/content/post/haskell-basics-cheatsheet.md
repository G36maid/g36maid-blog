# Haskell 基礎速查表：函式、串列與歸納

剛碰 Haskell 的那幾週，最困擾我的不是 monad，而是最基礎的語法散落在教材各章：`let` 和 `where` 長得像、guards 的管線符號看起來像邏輯運算、串列操作函式一堆名字記不住。後來我把上課前幾章的重點整理成三張速查表，之後每次在 GHCi 裡卡住就回來對照。這篇把那三張表重寫成可以直接貼進 GHCi 驗證的版本，補上範例輸出和我實際踩過的雷。

## 第一章：函式、區域綁定與運算子

| 語法 / 概念 | 意義 | 範例 |
| :--- | :--- | :--- |
| **`let ... in ...`** | 定義運算式內部的區域變數，整個 `let` 區塊本身是一個運算式 | `let x = 5 in x * 2` → `10` |
| **`where`** | 綁在函式定義上的區域宣告，作用域涵蓋整個函式子句 | `area r = pi * r^2 where pi = 3.14` |
| **Guards（`\|`）** | 一串條件分支，通常比巢狀 `if/then/else` 好讀 | `sign x \| x > 0 = 1 \| otherwise = 0` |
| **Currying** | 每次只吃一個參數，吃滿前回傳新函式 | `let add5 = (+) 5`，之後 `add5 3` → `8` |
| **`(.)` 組合** | `(g . f) x` 等於 `g (f x)`，從右往左接 | `let odd = not . even` |
| **`($)` 應用** | 低優先順序的函式套用，用來省括號 | `sum $ map (*2) [1..10]` → `110` |

這章有兩個我當初搞混很久的地方。第一是 `let` 與 `where` 的作用域差異：`let ... in ...` 是運算式，作用範圍只有 `in` 後面那段；`where` 綁在整個函式子句上，所以**跨所有 guards 共用**。想在一個函式的多個 guard 之間共用同一個區域變數，只有 `where` 寫得出來，這也是 HaskellWiki 的 [Let vs. Where](https://wiki.haskell.org/Let_vs._Where) 頁舉的第一個對比例子：

```haskell
signAbs x | x > 0     = a
          | otherwise = -a
          where a = abs x
```

第二是 `($)` 和 `(.)` 的優先順序。Haskell Report §4.4.2 定義 `(.)` 是 `infixr 9`、`($)` 是 `infixr 0`——一個最高、一個最低。所以 `sum $ map (*2) [1..10]` 沒問題，`$` 只是讓右邊先算完再丟給 `sum`；但 `sum . map (*2) [1..10]` 會直接編譯錯誤，因為 `(.)` 右邊必須是函式，而 `map (*2) [1..10]` 已經是串列了。想寫 point-free 得把資料留在最後：`sum . map (*2) $ [1..10]`。

## 第二章：串列

### 建構與基本操作

| 函式 | 型別 | 意義 | 範例 |
| :--- | :--- | :--- | :--- |
| **`:`（cons）** | `a -> [a] -> [a]` | 把元素接上串列開頭，O(1) | `1 : [2,3]` → `[1,2,3]` |
| **`(++)`** | `[a] -> [a] -> [a]` | 串接兩條串列，O(n) | `[1,2] ++ [3,4]` → `[1,2,3,4]` |
| **`head`** | `[a] -> a` | 第一個元素，**空串列會炸** | `head [1,2]` → `1` |
| **`tail`** | `[a] -> [a]` | 去掉第一個元素，**空串列會炸** | `tail [1,2]` → `[2]` |
| **`last`** | `[a] -> a` | 最後一個元素，**空串列會炸** | `last [1,2]` → `2` |
| **`init`** | `[a] -> [a]` | 去掉最後一個元素，**空串列會炸** | `init [1,2]` → `[1]` |
| **`(!!)`** | `[a] -> Int -> a` | 取索引處元素，**越界會炸** | `[1,2,3] !! 1` → `2` |
| **`length`** | `[a] -> Int` | 元素個數 | `length [1,2]` → `2` |
| **`null`** | `[a] -> Bool` | 是否為空串列 | `null []` → `True` |

### 高階函式

| 函式 | 型別 | 意義 | 範例 |
| :--- | :--- | :--- | :--- |
| **`map`** | `(a -> b) -> [a] -> [b]` | 對每個元素套函式 | `map (*2) [1,2]` → `[2,4]` |
| **`filter`** | `(a -> Bool) -> [a] -> [a]` | 保留滿足條件的元素 | `filter even [1,2,3,4]` → `[2,4]` |
| **`zip`** | `[a] -> [b] -> [(a,b)]` | 兩條串列配對，短的為準 | `zip [1,2] "ab"` → `[(1,'a'),(2,'b')]` |
| **`concat`** | `[[a]] -> [a]` | 攤平串列的串列 | `concat [[1],[2,3]]` → `[1,2,3]` |
| **`takeWhile`** | `(a -> Bool) -> [a] -> [a]` | 條件成立就一直取 | `takeWhile (<3) [1,2,3,1]` → `[1,2]` |
| **`dropWhile`** | `(a -> Bool) -> [a] -> [a]` | 條件成立就一直丟 | `dropWhile (<3) [1,2,3,1]` → `[3,1]` |

### List Comprehension

| 語法 | 意義 | 範例 |
| :--- | :--- | :--- |
| **`[out \| v <- list, guard]`** | 描述式地造出串列 | `[x*x \| x <- [1..5], odd x]` → `[1,9,25]` |

這章的雷最多。`head`/`tail`/`last`/`init` 對空串列全都直接丟例外，例如 `head []` 會吐出 `*** Exception: Prelude.head: empty list`，`(!!)` 越界同樣炸。防禦寫法是模式匹配：`f (x:xs) = ...` 配上 `f [] = ...`，或先用 `null` 檢查，再不然用 `case` 分支。讀到 `head` 出現在別人的程式碼裡，第一個該問的問題就是那條串列會不會是空的。

`takeWhile` 和 `filter` 的差別值得特別記：`takeWhile (<3) [1,2,3,4,5,4,3,2,1]` 碰到第一個 `3` 就停，回 `[1,2]`；`filter (<3)` 會掃完整條，回 `[1,2,1]`。差異在遇到條件不成立時要不要繼續掃。處理無限串列（如 `[1..]`）時只能用 `takeWhile`，用 `filter` 會算到天荒地老。

`zip` 遇到兩邊長度不同時以短的為準，多的元素直接丟掉——寫檔案解析時這行為有時是意外幫忙，有時是默默吃掉資料的 bug 來源。另外串列的 `(!!)` 是 O(n)，需要頻繁隨機存取的資料結構應該考慮 `Data.Sequence` 或陣列，這是串列教學常常沒講的代價。

## 第三章：結構歸納與 ⊥

| 概念 | 定義 |
| :--- | :--- |
| **串列的結構歸納** | 先證 `[]`（基底），再假設對 `xs` 成立、證 `(x:xs)`（歸納步驟） |
| **樹的結構歸納** | 先證 `Null`（基底），再假設對 `l`、`r` 成立、證 `(Node x l r)` |
| **`⊥`（bottom）** | 代表不終止的計算或錯誤，如 `undefined` |
| **Strict 函式** | `f ⊥ = ⊥`，遇到壞掉的輸入就跟著壞 |
| **Non-strict 函式** | `f ⊥` 可能照樣產出值，如 `const 1 ⊥` → `1` |

Haskell 是 non-strict 語言（習慣上說 lazy evaluation）：參數不會預先算成值，要用的時候才算。這不是修辭，是可以直接在 GHCi 觀察的行為——`const 1 undefined` 回 `1`，因為 `const` 根本不看第二個參數；`let x = undefined in 5` 也回 `5`，`x` 沒被用到就永遠不算。反過來，`length [undefined, undefined]` 回 `2`（長度不需要碰元素本身），但 `head [undefined]` 一定炸，因為取第一個元素就等於強制求值它。判斷一個函式是不是 strict，用 `undefined` 餵下去看會不會炸，是最直接的測試。

結構歸納和這套語意是相通的：證 `length` 的性質時，基底是 `length [] = 0`，歸納步驟假設 `length xs` 成立再證 `length (x:xs) = 1 + length xs`——這個遞迴定義本身就是 `map`、`filter` 這些函式的寫法，證明和程式碼是同一個形狀。lazy evaluation 的細節（thunk、WHNF、space leak）我在另一篇有更完整的整理，歡迎接著讀：[fp-lazy-eval-precision](/blog/fp-lazy-eval-precision/)。

## 收尾

這三張表到現在還貼在我的筆記牆上。我的用法是：語法類的問題（某函式型別、優先順序）直接開 GHCi 用 `:t` 查比翻文件快；語意類的問題（⊥、strictness、作用域）就值得回去讀 Haskell Report 對應章節，那些細節之後在讀別人的函式庫原始碼時會一直回來找你。
